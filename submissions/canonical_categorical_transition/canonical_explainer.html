One Layer Deeper · concept note

The canonical model: no hidden scratch paper

Our networks kept finding clever ways to look right without learning the arithmetic. This design removes every hiding place — and in doing so, it turned a vague failure ("it doesn't generalize") into a precise one we can attack.

task: x^(2^T) mod N idea: state = the answer itself finding: the data, not the model, is the wall
1

The whole task is one move, repeated

The benchmark asks: take a number x, square it, keep only the remainder after dividing by N — and do that T times in a row. That's it. The only move is “square, then wrap around N.”

So a model never needs to learn “the answer at depth 64.” It needs to learn the one move correctly, and then run it in a loop:

If the loop's single step is exactly right, every depth is free — depth 64 is just the step run 64 times. That's the prize. The catch is in the next section.

2

The loophole: hidden scratch paper

Training data only shows the model endpoints: the question and the final answer. It never shows the intermediate values in the chain. A typical neural network exploits that gap.

Most designs loop on an internal hidden state — a long list of unlabeled numbers — and only translate it into an answer at the very end, through a separate decoder. Nothing forces that hidden state to hold a real intermediate value. The network can scribble anything on its private scratch paper, as long as the final translation happens to match the training answers:

In the top design, gradient descent usually finds the lazy solution: memorize question→answer pairs inside the blob. The model aces training and collapses on any fresh number — which is exactly the failure we kept measuring.

The fix, in one sentence

Make the loop's state the answer itself — the ten possible decimal digits in each column, snapped to a definite readout — so the only way to be right at the end is to be right at every step along the way.

3

Why “canonical”?

A number has exactly one honest representation in this design: its digits. That's what canonical means here — one agreed-upon form, no private encodings. The model is built from three commitments:

  • Observable state. Between steps, the model may keep only a belief over the ten digits 0–9 in each column, plus a small set of named “modes” (think: carrying, comparing, done) — a short menu of labeled options, not a free-form memory.
  • Snap between steps (“straight-through” in the jargon): before the digits feed back into the loop, they're committed to a definite readout. Fuzzy, in-between states can't smuggle extra information forward.
  • One shared rule. A single learned circuit handles every digit column the same way and is reused at every depth. Learn it once, and it works on numbers of any length — which is what an unseen, larger modulus requires.

Note what is not in the design: no hand-coded arithmetic. The model still has to learn squaring and wrapping from examples. The architecture only guarantees that if it learns the right step, the step is reusable — memorization no longer has a place to live.

4

The proof that the idea works — in a small world

Does endpoint-only training ever suffice? We tested it where we could check everything: all moduli up to 31 — a world with only ~500 possible states. A model (essentially a lookup table with the canonical shape) was trained only on one-step questions and answers. It never saw a deeper example.

The clean result: with every one-step fact in training, the model was 100% correct at one step — and then 100% correct at depths 2, 4, 8, … 64, none of which it had ever seen. Endpoint-only supervision can teach a loopable rule. With only 60% of the facts, accuracy on withheld one-step questions fell to 6.57%, and deep rollouts to roughly a third.

5

The real wall: many rules fit the same data

Now the uncomfortable part. On the actual benchmark this canonical model scored about 0.4% — no better than its predecessors. The small-world proof tells us exactly why, and it isn't capacity or training speed.

The benchmark's numbers are hundreds of digits long. Its training set — a few thousand examples — covers a vanishing sliver of possible one-step facts. And a flexible learned rule is like a form with many blanks: the training data fills in a few, and everything consistent with those blanks is a rule the model might settle on. The reframe

Before: “our models can't compute modular squaring.” After: “the training endpoints don't single out which rule to learn.” The canonical design guarantees a correct rule would loop perfectly — but the data never points the optimizer at the correct rule. The wall is identifiability, not architecture, capacity, or compute.

This is a genuinely better problem to have, because it dictates the moves. More optimizer tricks, wider networks, and longer training all polish the wrong thing — our experiment table shows dozens of them landing in the same 0.3–1% band. What can work is narrowing the blanks or adding constraints:

  • Shrink the rule class. Structure the learned step (e.g., around a division-free reduction scheme) so far fewer wrong rules are expressible — then the same endpoints pin down more.
  • Mine the depth rungs. Training data includes T=1, 2 and 3 for related inputs; used carefully (and within the rules), consecutive rungs constrain the step, not just the endpoint.
  • Local learning signals. Give each step of the loop its own nudge toward consistency, instead of one end-of-chain grade diluted across every step.

The concept on one card

Canonical model — a looped network whose only carried state is the thing being computed: the digits of the current number, snapped to a definite readout between steps, transformed by one shared rule.

closes: memorize-and-decode loophole guarantees: right step ⇒ right at any depth doesn't guarantee: data picks the right step next: make the data identify the rule

It didn't beat the benchmark. It did something arguably more valuable: it isolated the one question that decides this challenge — can the available endpoints be made to identify a reusable squaring step? Every next experiment now attacks that question directly.
